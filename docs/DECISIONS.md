## QRVM facts the code must respect (verified in the client and compiler sources)

- `mload`, `mstore` and `calldataload` move 64 bytes; `mstore8` is unchanged; memory grows in 64-byte words with expansion cost `3w + w^2/512`. Free memory pointer at `0x80`, initial value `0x100`, scratch space `0x00` to `0x7f`.
- Assembly `keccak256(p, n)` returns the 256-bit digest right-aligned in the 512-bit word; high-level `keccak256()` returns a left-aligned `bytes32`. All digest handling lives in assembly. Merkle compression: `mstore(0x00, or(shl(256, left), right)); parent := keccak256(0x00, 64)`.
- `calldataload` past the end zero-pads, so the exact-length check runs before any query data is read.
- Yul is full solc-0.8.24 Yul with unchanged opcode names; `addmod` and `mulmod` are 512-bit in assembly; `unchecked`, `immutable`, libraries, calldata slicing, custom errors, `--via-ir` and `verbatim` are available.
- ABI: every static type pads to 64 bytes; the selector stays 4 bytes; a dynamic `bytes` tail is a 64-byte length word plus data padded to 64; log topics are 64 bytes with `bytes32` and the event signature hash left-aligned.
- Precompiles are pre-warmed: a STATICCALL to `0x03`, `0x05` or `0x06` costs 100. Builtins `shake256(bytes) returns (bytes64)` and `mldsa87verify(bytes64, bytes, bytes, bytes) returns (bool)` exist. Modexp header fields are 32-byte lengths.
- Calldata costs 16 gas per non-zero byte and 4 per zero byte; the transaction base cost is 21,000; `qrl_estimateGas` caps at 50,000,000, so an estimate can exceed the block cap.
- `gqrl --dev` exists with `--dev.period`, `--dev.gaslimit`, chain id 1337, a funded unlocked developer account and a simulated beacon; the precompile stubs `0x01` to `0x06` are pre-allocated in its genesis.

## Risks tracked

1. Plonky3 shape churn between `0.7.0-rc.1` and the final release: pinned version and lockfile; the calldata layout carries a version byte.
2. Transcript subtleties (three instance observations, end-of-digest sampling, chaining value, rejection sampling, `checkPow(0)` no-op, `log_arity` observed after `final_poly`, `sample_bits` consuming a full u64): byte-level logging and the M3 replay test come before any Merkle or FRI code.
3. Keccak alignment and 64-byte `mstore` clobbering: all digest work in assembly; harness tests on known keccak vectors first.
4. `calldataload` zero padding: exact-length check first; offsets unit-tested against the Rust layout.
5. Code size and gas caps: measured at M6 with three flag sets; documented splits.
6. Dev node versus Kurtosis (chain id, signing path, gas limit source): `scripts/lib/rpc.js` and `scripts/lib/devAccount.js` abstract both; Kurtosis is the release gate.
7. Offline toolchains: the first `cargo build` and `make gqrl` need network access.
8. Docker and Kurtosis state: the daemon must be started; enclaves are recreated, never resumed; a separate image namespace avoids collisions with `qrl2-qns`.
9. Duplicate query indices at small n: representative and consistency rules covered by a forced-collision vector.
10. Licensing: Plonky3 is MIT/Apache-2.0 and the copied Fibonacci AIR keeps its notice; the repository is GPL-3.0.
11. QNS review timing: the snapshot commits duplicate the uncommitted alignment; rebase and drop them once the QIP branch is committed.
