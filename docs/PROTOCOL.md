# QuantaProof protocol contract (Plonky3 uni-stark, Goldilocks, keccak256)

This document is the normative, byte-exact description of what the QuantaProof on-chain verifier
must compute. Every statement is derived from the pinned Plonky3 sources (crates.io
`0.7.0-rc.1`, see `prover/PLONKY3_VERSION`) and confirmed by byte-level logging of the unmodified
upstream `prove` / `verify` functions (`prover/stark-prover/src/challenger.rs`) against the
independent mirror verifier (`prover/stark-prover/src/mirror.rs`). Source citations use the form
`crate/file.rs:lines` and refer to the rc.1 crate sources as published on crates.io.

The Rust mirror, the JS references and the Hyperion contracts must agree with this document.
Where the approved plan assumed a shape that differs from reality, section 14 records the
deviation.

## 1. Scope and pinning

- Proof system: `p3-uni-stark` over Goldilocks with `TwoAdicFriPcs`, one AIR (the upstream
  Fibonacci test AIR, copied verbatim into `prover/stark-prover/src/fib_air.rs`), no ZK, no
  preprocessed columns, no periodic columns.
- Plonky3 version: `0.7.0-rc.1` for every `p3-*` crate (`prover/Cargo.lock` is committed).
- Field: Goldilocks `p = 2^64 - 2^32 + 1 = 0xFFFFFFFF00000001` (`p3-goldilocks/src/goldilocks.rs:29`).
- Challenge field: `EF = F[X] / (X^2 - 7)` (`p3-goldilocks/src/extension.rs:25`).
- Hash: keccak256 everywhere (leaf hashing, Merkle compression, Fiat-Shamir).

## 2. Notation and wire encodings

- `F`: a base field element. Wire form: the canonical value (`< p`) as an 8-byte little-endian
  u64. This is exactly what Plonky3 hashes and observes (`p3-field/src/integers.rs:563-565`
  `into_bytes = to_unique_u64().to_le_bytes()`, `p3-challenger/src/serializing_challenger.rs:263-267`
  `observe = observe_slice(&value.to_unique_u64().to_le_bytes())`, where `to_unique_u64` is
  `as_canonical_u64`, `p3-field/src/field.rs:1193-1196`). A value `>= p` on the wire is
  rejected (`NonCanonicalElement`).
- `EF`: an extension element `c0 + c1 X`. Wire form: `F(c0) || F(c1)` (16 bytes). Observing an
  `EF` observes its basis coefficients in order (`p3-challenger/src/lib.rs:107-108`); sampling
  an `EF` samples `c0` then `c1` (`lib.rs:125-126`).
- `D`: a 32-byte keccak256 digest, raw bytes.
- `n = degree_bits`: `log2` of the trace length. `lb = log_blowup`. `H = n + lb`: `log2` of
  every LDE height. `lf = log_final_poly_len`. `Q = num_queries`. `R`: number of FRI rounds.
- `g_i = TWO_ADIC_GENERATORS[i]` (order `2^i`), `rev(x, b)`: bit reversal of `x` within `b`
  bits.

## 3. Constants

`prover/constants.json` (generated by `stark-prover constants`) lists `p`, `p - 1`,
`epsilon = 2^64 mod p = 2^32 - 1`, `INV2 = (p + 1) / 2 = 0x7FFFFFFF80000001`, `W = 7`,
`GENERATOR = 7`, `TWO_ADIC_GENERATORS[0..=32]` and their inverses, and the 512-bit lane masks.
Invariants checked in `constants.rs` tests: `g_0 = 1`, `g_i * ginv_i = 1`, `g_i^(2^i) = 1`,
`g_i^(2^(i-1)) = -1` for `i >= 1`, `g_{i+1}^2 = g_i`, `2 * INV2 = 1`.

## 4. Challenger semantics

The transcript is `SerializingChallenger64<Goldilocks, HashChallenger<u8, Keccak256Hash, 32>>`.

`HashChallenger` (`p3-challenger/src/hash_challenger.rs`) keeps an input buffer and an output
buffer of bytes:

1. `observe(byte)` clears the output buffer, then appends the byte to the input buffer
   (`hash_challenger.rs:51-56`). Any unread sampled bytes are therefore discarded by the next
   observe.
2. `sample()` with an empty output buffer performs a flush: `D = keccak256(input_buffer)`, the
   input buffer becomes exactly `D` (drained, then extended with the 32 digest bytes) and the
   output buffer becomes `D` (`hash_challenger.rs:36-43`, `130-137`). Then one byte is popped from
   the END of the output buffer.
3. The initial state is empty: the first flush hashes exactly the bytes observed so far.

`SerializingChallenger64` (`p3-challenger/src/serializing_challenger.rs`):

4. `observe(F)`: eight little-endian bytes (`263-267`). `observe(MerkleCap)`: the 32 raw bytes of
   the single root (`290-299`). Public values use `observe_slice`, one element at a time.
5. `sample_u64`: `sample_array::<8>()` pops eight bytes `b0..b7` (`b0` is the last byte of the
   output buffer) and reads them as `u64::from_le_bytes([b0..b7])` (`336-354`). With `D` viewed
   as a 256-bit big-endian integer this is group `k = 0..3` of `D`:
   `group_k = (D >> 64k) & (2^64 - 1)`, consumed in the order `k = 0, 1, 2, 3`; group 0 is
   `D[24..32]` read big-endian. No byte shuffling is needed on a big-endian machine word.
6. `sample() -> F`: `log2_ceil(p) = 64`, so the mask is `2^64 - 1` and has no effect; the u64 is
   accepted when `< p`, otherwise rejected and the next group is drawn (`336-354`). The rejection
   probability is `2^-32` per draw.
7. `sample_bits(b)`: one full u64 group, masked to its low `b` bits (`362-367`). It never
   rejects. Requires `2^b < p`.
8. `check_witness(bits, w)` (`p3-challenger/src/grinding_challenger.rs:42-48`): with
   `bits == 0` it returns true without touching the transcript; otherwise it observes `w` as
   an `F` and requires `sample_bits(bits) == 0`. The prover's `grind` returns witness `0` for
   `bits == 0` (`serializing_challenger.rs:405-424`), so with the presets above every commit PoW
   witness on the wire is the field element `0`, and the verifier never reads it.
9. After four samples the output buffer is empty; a fifth sample re-flushes with the input buffer
   equal to `D` alone (nothing was observed in between), so `D' = keccak256(D)`.

## 5. Transcript order

The verifier (`p3-uni-stark/src/verifier.rs:287-561`, `p3-fri/src/two_adic_pcs.rs:684-715`,
`p3-fri/src/verifier.rs:158-437`) and the prover (`p3-uni-stark/src/prover.rs:224-395`,
`p3-fri/src/prover.rs:43-160`, `192-286`) execute the same sequence. Byte counts are for the
Fibonacci AIR (width 2, three public values, one quotient chunk).

1. observe `F(degree_bits)` (`verifier.rs:412`)
2. observe `F(base_degree_bits)`; equals `degree_bits` because `is_zk = 0` (`verifier.rs:413`)
3. observe `F(preprocessed_width)`, always `F(0)` (`verifier.rs:414`)
4. observe `trace_root` (32 bytes, `verifier.rs:420`)
5. observe `public_values[0..3]` (3 F, `verifier.rs:424`)
6. sample `alpha` (EF, `verifier.rs:430`); this is the first flush, over the 80 bytes of steps 1 to 5
7. observe `quotient_root` (32 bytes, `verifier.rs:431`)
8. sample `zeta` (EF, `verifier.rs:442`)
9. require `zeta^(2^n) != 1` (`verifier.rs:447-449`, `OodPointInDomain`) and set
   `zeta_next = zeta * g_n` (`verifier.rs:458-460`, `p3-commit/src/domain.rs:215-217`)
10. observe the opened values in (round, matrix, point) order (`two_adic_pcs.rs:695-701`):
    `trace_local` (2 EF), `trace_next` (2 EF), `quotient_chunk` (2 EF): 96 bytes
11. sample `fri_alpha` (EF, `p3-fri/src/verifier.rs:195`)
12. for each round `r = 0..R`: observe `fri_commit[r]` (32 bytes); `check_witness(commit_pow_bits,
    commit_pow_witness[r])`; sample `beta[r]` (EF) (`verifier.rs:292-306`)
13. require `final_poly.len() == 2^lf` and observe `final_poly[0..2^lf]` (EF each, `verifier.rs:308-317`)
14. for each round: observe `F(log_arity[r])` (`verifier.rs:319-322`)
15. `check_witness(query_pow_bits, query_pow_witness)` (`verifier.rs:324-327`, `PowFailed`): with
    16 bits this observes the witness (8 bytes) and requires the next `sample_bits(16)` to be 0
16. for `q = 0..Q`: `index[q] = sample_bits(H)` (`verifier.rs:333-338`); nothing is observed
    between the samples, so the groups run through successive `keccak256(D)` chains

Observed transcript of `test/vectors/fib_c3_n10.json` (n = 10, R = 3, lf = 3, Q = 34):
flush[0] hashes 80 bytes (steps 1 to 5) and serves `alpha`; flush[1] hashes 64 bytes
(`D0 || quotient_root`) and serves `zeta`; flush[2] hashes 128 bytes (`D1 || openings`) and
serves `fri_alpha`; flush[3..6) hash 64 bytes each (`D || fri_commit[r]`) and serve the betas;
flush[6] hashes 192 bytes (`D5 || final_poly (128) || log_arity (24) || query_pow_witness (8)`)
and serves the query PoW group and the first three indices; flush[7..15) are the `keccak256(D)`
chain that serves the remaining 31 indices (4 per flush). In total 464 bytes are observed and
376 bytes are sampled; the raw byte transcript has 14 alternating observe/sample runs.

## 6. Domains, coset, opening points

- Trace domain: the subgroup `<g_n>` of size `2^n` (shift 1) (`two_adic_pcs.rs:284-286`).
- Every committed LDE is evaluated on the coset `7 * K`, `|K| = 2^H`, and stored with rows in
  bit-reversed order (`two_adic_pcs.rs:300-324`, shift `= GENERATOR / domain.shift()`).
- Quotient: the constraint degree hint is 2, so `log_num_quotient_chunks = log2_ceil(1) = 0`
  (`p3-uni-stark/src/symbolic.rs:22-24`): exactly one chunk, committed on `7 * K` with the same
  height `2^H` as the trace, width 2 (the two basis coefficients of the extension-valued
  quotient) (`prover.rs:298-320`).
- Query point of query `q` with index `idx` (H bits): `x = 7 * g_H^rev(idx, H)`
  (`p3-fri/src/verifier.rs:740-744`, `bits_reduced = 0` because both batches have height `2^H`).

## 7. Reduced openings (FRI input)

For each query (`p3-fri/src/verifier.rs:736-760`, `770-816`), with `alpha = fri_alpha` and the
alpha power counter shared across both batches at height `H`:

```
d0 = zeta - x,  d1 = zeta_next - x          (ZeroDenominator when either is 0)
ro = alpha^0 (trace_local[0] - row_t[0]) / d0 + alpha^1 (trace_local[1] - row_t[1]) / d0
   + alpha^2 (trace_next[0]  - row_t[0]) / d1 + alpha^3 (trace_next[1]  - row_t[1]) / d1
   + alpha^4 (quotient_chunk[0] - row_q[0]) / d0 + alpha^5 (quotient_chunk[1] - row_q[1]) / d0
```

`row_t` and `row_q` are the opened trace and quotient rows of the query (base field). The
denominators are batch-inverted upstream; any inversion strategy gives the same values.

## 8. FRI

### 8.1 Arity schedule

Rounds fold from height `H` down to `lb + lf`. Round `r` uses `log_arity[r] = min(max_log_arity,
remaining)` where `remaining` starts at `n - lf` and decreases by each round's arity
(`p3-fri/src/config.rs:180-207`, `prover.rs:217-231`, single input height). The verifier reads
the arities from the proof and enforces `1 <= log_arity[r] <= max_log_arity`
(`p3-fri/src/proof.rs:51-56`, `verifier.rs:207-221`) and `sum(log_arity) + lb + lf == H`
(`verifier.rs:248-283`).

### 8.2 Rows and positions

Round `r` commits the folded codeword (height `2^{h_r}`, `h_0 = H`) as a matrix of width
`arity_r = 2^{k_r}` over `EF` (`prover.rs:233-238`), so its Merkle tree has `2^{h_r - k_r}`
leaves. For a query with index `idx` entering the round: `position = idx mod arity_r`,
`group = idx >> k_r` (the leaf index and the next round's index). The reconstructed row has the
query's current value at `position` and the proof's `sibling_values[q]` (exactly `arity_r - 1`
values) at the other positions in ascending order (`verifier.rs:522-533`, prover
`prover.rs:337-356`).

### 8.3 Folding

`folded = fold_row(group, h_r - k_r, k_r, beta_r, row)` (`verifier.rs:544-550`). The literal
definition (`two_adic_pcs.rs:108-131`, `219-259`) is barycentric Lagrange interpolation at
`beta_r` of the row over the points `xs[i] = s * g_{k}^rev(i, k)` with
`s = g_{h + k}^rev(group, h)` (`h = h_r - k_r`), where `row[i]` is the value at `xs[i]`.

The on-chain form is the binary decomposition (`two_adic_pcs.rs:163-169` documents the prover's
identical decomposition). With `m = k`, `s` and `b = beta_r`, repeat `k` times: pair
`(row[2j], row[2j+1])`, which sit at `(y, -y)` with `y = s * g_m^rev(j, m-1)`, fold to
`(lo + hi) / 2 + b * (lo - hi) / (2y)`, then set `s <- s^2`, `b <- b^2`, `m <- m - 1`. The single
remaining value is `folded`. The mirror computes both forms and asserts equality on every
(query, round) of every vector; the integration tests also compare both with the upstream
`fold_row`.

No reduced opening is rolled in after round 0 for this AIR (both input batches live at height
`H`, `verifier.rs:567-571` never fires).

### 8.4 Final polynomial

After the last round the index `idx_R` has `lb + lf` bits. The check is
`horner(final_poly, g_H^rev(idx_R, H)) == folded` (`verifier.rs:392-404`), with
`final_poly[0]` the constant term (`p3-field/src/helpers.rs:417-439`). The evaluation point
carries no coset shift. Failure: `FinalPolyMismatch`.

### 8.5 Per-round Merkle checks

Round `r` verifies the multi-opening of the rows collected above against `fri_commit[r]` with
dimensions `{ width: arity_r, height: 2^{h_r - k_r} }` and the group indices as leaf indices
(`verifier.rs:409-435`). `ExtensionMmcs` flattens each row to `2 * arity_r` base elements
(`p3-commit/src/adapters/extension_mmcs.rs:112-144`), so the leaf preimage is the row in wire
form (`arity_r * 16` bytes).

## 9. Merkle trees and pruned multi-openings

- Leaf digest: `keccak256` of the row bytes. `SerializingHasher` streams the row elements as
  canonical little-endian u64 words (`p3-symmetric/src/serializing_hasher.rs:22-33`,
  `p3-merkle-tree/src/merkle_tree.rs:268-338` hash one row per leaf). For the input batches the
  leaf is `keccak256(F(row[0]) || F(row[1]))` (16 bytes); for round `r` it is the `arity_r`
  extension values in wire order.
- Compression: `parent = keccak256(left || right)` (`p3-symmetric/src/compression.rs:61-70`,
  inputs in child-position order).
- Every tree here is a full binary tree of `2^h` leaves: `N = 2`, one matrix per commitment,
  so the arity schedule is all 2s and no injection layer exists (`merkle_tree.rs:229-244`,
  `473-481`). Cap height 0: the commitment is the single root (`MerkleCap` with one entry,
  `mmcs/mod.rs:786-791`).
- Multi-opening (`Mmcs::verify_multi_batch`, `mmcs/batch.rs:287-296` delegating to
  `verify_batch_pruned`, `mmcs/mod.rs:450-794`):
  1. `sorted_unique` = the query indices sorted ascending with duplicates removed
     (`mmcs/mod.rs:527-530`). The representative of a duplicated leaf is the first query (in
     query order) that opens it; every other query opening the same leaf must carry an identical
     row, otherwise `DuplicateOpeningMismatch` (`mmcs/mod.rs:545-558`). This check runs before
     any hashing.
  2. Frontier walk (`p3-merkle-tree/src/pruning.rs:130-176`, used by both `prune_paths` and
     `restore_paths`): starting from the sorted unique leaves, process each level from the
     leaves upward; nodes are grouped by parent (`index >> 1`) in ascending order; within a
     group the child positions 0 and 1 are visited ascending, and a position that no frontier
     node occupies consumes the next sibling digest from the proof. The proof is the flat list of
     exactly those boundary digests in that order (`pruning.rs:83-89`), level 0 first.
  3. The number of digests the walk consumes is determined by the indices alone; the proof must
     carry exactly that many (`pruning.rs:304-311`), otherwise `SiblingCountMismatch`. This check
     also runs before hashing.
  4. Hash walk: leaf digests for the unique leaves, then per level `keccak256(left || right)`;
     the single surviving digest must equal the root, otherwise `MerkleRootMismatch`
     (`mmcs/mod.rs:648-712`, `786-791`).
- The verifier supplies the indices from its own transcript; the proof stores no indices.

## 10. Constraint evaluation at `zeta`

Selectors of the trace domain (shift 1, `p3-commit/src/domain.rs:306-315`), all in `EF`:

```
zH      = zeta^(2^n) - 1
isFirst = zH / (zeta - 1)
isLast  = zH / (zeta - g_n^-1)
isTrans = zeta - g_n^-1
invVan  = 1 / zH
```

Constraints in emission order (`fib_air.rs`; `when_first_row` etc. multiply by the selector,
`p3-air/src/builder.rs:94-123`, `filtered.rs:56-58`; `assert_eq(x, y)` is `assert_zero(x - y)`,
`builder.rs:157-159`), with `l = trace_local`, `nx = trace_next`, `[a, b, x]` the public values:

1. `isFirst * (l[0] - a)`
2. `isFirst * (l[1] - b)`
3. `isTrans * (l[1] - nx[0])`
4. `isTrans * (l[0] + l[1] - nx[1])`
5. `isLast * (l[1] - x)`

Accumulator (`p3-uni-stark/src/folder.rs:374-377`): `acc = 0; for c in constraints: acc = acc * alpha + c`,
so `acc = c1 alpha^4 + c2 alpha^3 + c3 alpha^2 + c4 alpha + c5` with `alpha` from transcript step 6.

Quotient recomposition (`verifier.rs:98-135`, one chunk so the Lagrange factor is 1;
`p3-field/src/field.rs:1249-1255` lifts the two opened coefficients as `q0 + X q1`):
`quotient = (q0.c0 + 7 q1.c1, q0.c1 + q1.c0)`.

Check (`verifier.rs:196`): `acc * invVan == quotient`, otherwise `OodMismatch`.

## 11. Calldata layout v1

`bytes calldata proof` is a lossless canonical encoding of `Proof<Config>`; `publicValues` is a
separate 24-byte argument (`F(a) || F(b) || F(x)`). All multi-byte integers inside the layout are
field elements (little-endian) except `sib_count`, which is a big-endian u16.

### 11.1 Transcript prefix

| Offset | Size | Field |
|---|---|---|
| 0 | 1 | `version = 0x01` |
| 1 | 1 | `degree_bits = n` |
| 2 | 1 | `num_rounds = R` |
| 3 | R | `log_arity[0..R]` (one byte each) |
| 3 + R | 32 | `trace_root` |
| 35 + R | 32 | `quotient_root` |
| 67 + R | 32 | `trace_local` (2 EF) |
| 99 + R | 32 | `trace_next` (2 EF) |
| 131 + R | 32 | `quotient_chunk` (2 EF: the two basis coefficients of the single chunk) |
| 163 + R + 40 r | 32 | `fri_commit[r]` for `r = 0..R` |
| 195 + R + 40 r | 8 | `commit_pow_witness[r]` (F) |
| 163 + 41 R | 16 * 2^lf | `final_poly[0..2^lf]` (EF each, constant term first) |
| 163 + 41 R + 16 * 2^lf | 8 | `query_pow_witness` (F) |
| `pEnd = 171 + 41 R + 16 * 2^lf` | | end of the prefix |

`proofId = keccak256(proof[0..pEnd])`. Every transcript input of sections 5.1 to 5.15 except the
public values lives in the prefix.

### 11.2 Query data

Immediately after the prefix, in this order:

| Block | Content |
|---|---|
| trace batch | `rows[Q]` (each `F(row[0]) || F(row[1])`, 16 bytes) then `sib_count` (u16 BE) then `sib_count` digests of 32 bytes in frontier wire order |
| quotient batch | same shape (`rows[Q]` of 16 bytes, `sib_count`, digests) |
| round r (for r = 0..R) | `sibling_values[Q][arity_r - 1]` (EF each, per query the values at the positions other than the query's own, ascending) then `sib_count` then the digests |

Offsets: `trace.rows = pEnd`; `trace.sib_count = pEnd + 16 Q`; `trace.siblings = trace.sib_count + 2`;
`trace.end = trace.siblings + 32 * sib_count`; each following block starts at the previous
block's `end`; round `r`'s `sib_count` sits at `start + 16 Q (arity_r - 1)`. The exact-length
rule: the `end` of the last block must equal `proof.length`. Because `calldataload` past the end
zero-pads, the verifier must compute the expected length from the header and the `sib_count`
fields (each read at an offset that is itself within bounds) before reading any element.

Worked example (`fib_c3_n10`, R = 3, lf = 3, Q = 34): `pEnd = 422`; trace rows 422..966,
`sib_count` at 966 (= 250), siblings 968..8968; quotient rows 8968..9512, `sib_count` at 9512
(= 250), siblings 9514..17514; round 0 (arity 8) sibling values 17514..21322 (34 * 7 * 16),
`sib_count` at 21322 (= 148), siblings 21324..26060; round 1 (arity 8) 26060..31534 (52
siblings); round 2 (arity 2) 31534..32848 (24 siblings); total 32848 bytes.

### 11.3 Decoding rules and error precedence

1. `proof[0] != 1` -> `BadVersion` (an empty proof is `BadLength`).
2. Header (`BadHeader`): `1 <= n`, `n + lb <= 32`, `n >= lf`, every `log_arity[r]` in
   `1..=max_log_arity`, `sum(log_arity) == n - lf`. `R` and the arities are trusted only after
   these checks; `R = 0` is legal only when `n == lf`.
3. Length (`BadLength`): every `sib_count` field must lie inside the proof and the computed
   total must equal `proof.length`.
4. Elements (`NonCanonicalElement`): every `F` in the prefix and in the query data must be `< p`.
   Digests are raw bytes with no constraint.
5. Only then does verification start (section 12).

With `commit_proof_of_work_bits = 0` the `commit_pow_witness[r]` bytes are encoded (they are part
of `Proof`) but never observed; the verifier accepts any canonical value there, so `proofId` is
malleable in those 8 R bytes. Fact registries must therefore key facts by the public values (the
plan does), never by `proofId` alone.

## 12. Verifier check order and errors

The on-chain verifier and the mirror run these steps in this order. The order fixes which error
a malformed proof raises and is part of the contract:

1. Decode (section 11.3): `BadVersion`, `BadHeader`, `BadLength`, `NonCanonicalElement`.
2. Transcript steps 1 to 10; `OodPointInDomain` after `zeta`.
3. Constraint identity (section 10): `OodMismatch`. This runs before any FRI work because it
   needs only the prefix and fails fast.
4. Transcript steps 11 to 16: `PowFailed` (commit PoW rounds first, then the query PoW).
5. Input batches, trace then quotient (section 9): `DuplicateOpeningMismatch`, then
   `SiblingCountMismatch`, then `MerkleRootMismatch`.
6. Reduced openings (section 7): `ZeroDenominator`.
7. Fold chains, query by query (section 8.3, 8.4): `FinalPolyMismatch`.
8. Per-round Merkle checks (section 8.5), round by round, with the same three Merkle errors.

Custom errors: `BadVersion`, `BadHeader`, `BadLength`, `NonCanonicalElement`, `PowFailed`,
`SiblingCountMismatch`, `MerkleRootMismatch`, `DuplicateOpeningMismatch`, `FinalPolyMismatch`,
`OodPointInDomain`, `OodMismatch`, `ZeroDenominator`. `OodPointInDomain` and `ZeroDenominator`
are unreachable by mutating a valid proof (they need a transcript output in a set of measure
`2^-64`); they exist so the verifier never divides by zero.

## 13. Vector files

`test/vectors/fib_<preset>_n<N>.json` (tracked for `N <= 12`; larger sizes go to
`test/vectors/large/`, which is gitignored) with `schema: 1`:

- `plonky3Version`, `name`, `config` (`logBlowup`, `logFinalPolyLen`, `maxLogArity`,
  `numQueries`, `commitPowBits`, `queryPowBits`), `air: "fibonacci"`, `degreeBits`,
  `publicValues` (decimal strings), `proofHex`, `publicValuesHex`, `proofLength`, `proofId`.
- `layout`: `pEnd`, `prefix` offsets, `blocks[]` (`name`, `rowsOffset`, `rowsLen`,
  `sibCountOffset`, `siblingsOffset`, `sibCount`, `end`) and `rounds[]` (`logArity`,
  `siblingValuesOffset`, `siblingValuesLen`, `sibCountOffset`, `siblingsOffset`, `sibCount`, `end`).
- `transcript[]`: events `{op: observe|flush|sample_u64|sample_field|sample_bits|check_pow, label, ...}`;
  `observe` and `sample_u64` carry the bytes, the others annotate them (`sample_u64.bytes` are
  the eight bytes in the order popped; `value` is their little-endian u64).
- `challenges`: `alpha`, `zeta`, `zetaNext`, `friAlpha`, `betas[]`, `indices[]`.
- `openInputs[]`: per query `index`, `x`, `denomZeta`, `denomZetaNext`, their inverses,
  `traceRow`, `quotientRow`, `reducedOpening`.
- `fold[]`: per (query, round) `index`, `position`, `row[]`, `foldedIndex`, `subgroupStart`,
  `folded` (binary form), `foldedBarycentric`, `leafDigest`.
- `finalPolyChecks[]`: per query the final `index`, `x` and the polynomial value.
- `merkle[]`: per block `logHeight`, `indices`, `sortedUnique`, `sibCount`, `leaves[]`,
  `levels[][]` (frontier digests per level, root last), `root`.
- `constraints`: `zH`, `isFirst`, `isLast`, `isTrans`, `invVan`, `values[]`, `acc`, `quotient`.
- `expected: {valid: true}`.

Field elements are decimal strings, `EF` values are `[c0, c1]` pairs, bytes and digests are
`0x`-hex, offsets and indices are JSON numbers. Mutated vectors carry `name`, `source`, the
parameters, `proofHex`, `publicValuesHex`, `proofLength` and
`expected: {valid: false, error, mutation}`.

## 14. Deviations from the plan

- The plan's assumed transcript, challenger semantics, Merkle wire order and calldata layout all
  hold at rc.1. Two details are now fixed precisely: `sib_count` is big-endian, and the
  `fold_row` coset start uses the folded index and folded height (`s = g_{h+k}^rev(group, h)`).
- Check order: the plan listed the constraint identity as the last step (after `pcs.verify`,
  as upstream does). The contract moves it directly after the opened values are absorbed
  (section 12, step 3). This changes no accept/reject decision, only which error fires first;
  it lets the verifier fail fast and makes `OodMismatch` reachable by mutation.
- Upstream verifies both input batches before computing any reduced opening and runs every fold
  chain before any per-round Merkle check; the contract keeps that order (section 12, steps 5 to 8).
- With commit PoW bits `= 0` the witnesses are still encoded (8 bytes per round, value 0 from
  upstream) and are transcript-inert; see section 11.3 on `proofId` malleability.
- The plan's `checkPow(0, w)` no-op, END-of-digest group order, 2^-32 rejection sampling and
  `sample_bits` consuming a full u64 group were all confirmed by the logged transcript.
- The `sizes` gas model is the plan's formula; measured values replace it in `docs/GAS-REPORT.md`.
